# 遇到的问题与处理思路

## 1. 原有切换器无法识别 2.8

本次调查使用的已安装切换器为 Cavalry Language Switcher 1.0.6，目标是较早的 2.7.2 结构。目标 2.8.0 改变了语言资源目录与文件形式，Qt 版本也不同。只让选择框显示一个目录，不能完成真正的适配。

处理思路是重新确认 2.8 的资源布局与目标文件，按原始文件指纹判断兼容性。当前实现采用默认英文语言资源位置的显示文本替换，没有新注册独立的简体中文语言选项。

## 2. 翻译时需要保留软件内部标识

语言资源同时包含用于显示的文字和程序识别字段。如果混改内部类型、标识或占位符，可能影响连接、菜单或属性读取。

本次将修改范围限定在显示文本，保留内部标识、结构、占位符和 HTML，并进行离线一致性检查。翻译增量既来自已有词库，也来自对新增内容和遗漏项的补充。

## 3. 中文字体与英文界面的观感不一致

初版中文界面出现了用户不喜欢的衬线显示观感。本次改为在 Windows 主题字体设置中使用 Noto Sans SC，保留字体字号等其他设置。

字体内存加载已经验证；具体界面观感需要重启目标 Cavalry 后检查，不能仅根据配置写入成功就认定完成验收。

## 4. 中文名称不方便对照英文教程

仅显示中文会增加对照英文教程的成本；仅显示英文又不便于中文理解。本次将目录名称整理为中文与完整英文并列的形式，并保留原来的内部标识。

名称数据中的中英文匹配已经检查，应用内实际搜索仍需要结合目标构建验证。示例见双语术语文档。

## 5. 文件夹选择与自动查找不直观

早期界面虽然提示选择文件夹，实际使用的却是程序文件选择窗口，容易让使用者不断进入子目录。v1.0.1 分为真正的文件夹选择和独立的程序 / 快捷方式选择，并补充了运行位置、快捷方式和常见安装来源发现。

用户也可粘贴路径。位置解析与查找逻辑经过隔离测试，具体电脑上的目录与权限情况仍需要实际反馈。

## 6. 缺少主题文件时，其他问题被遮住

测试反馈出现缺少主题资源的错误。早期流程在读取主题时直接异常，遮住了先前收集到的其他资源问题。

v1.0.1 先收集资源完整性信息，再决定是否继续。检查不通过时停止写入，并提供目录诊断。反馈电脑上缺失资源的实际原因尚未查明，没有通过补建空目录或强制覆盖来绕过检查。

## 7. 重复安装与恢复需要保护最初备份

修复不能把已经修改过的文件当作新的原版备份。本次保留首次备份，结合状态记录和指纹处理重复安装与恢复，同时尽量保留之后调整的主题设置。

这些流程通过隔离功能测试；它们仍不能代替另一台真实电脑上的完整使用验收。
